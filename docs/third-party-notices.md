# Third-party notices

> Slate redistributes a small set of open-source components inside its runtime. This page lists
> each one, its license, and where its full license text travels. It covers third-party material
> only and does not grant a license to Slate itself.

## What is redistributed

`runtime-host sync` copies `shell/vendor/` and `shell/canvas/` into every host, and the GitHub
Pages build publishes the same files. Each directory carries the complete license texts for what
it contains:

| Runtime directory | Contents | Full license texts |
| --- | --- | --- |
| `shell/vendor/` | Viewer libraries and the icon font | `shell/vendor/LICENSES/` |
| `shell/canvas/` | The bundled Canvas application | `shell/canvas/THIRD_PARTY_NOTICES.txt`, generated by the Canvas build |

## Host responsibilities

- Keep `shell/vendor/LICENSES/` and `shell/canvas/THIRD_PARTY_NOTICES.txt` with the runtime.
  Synchronization copies them, and `runtime-host check` reports them if they are removed or changed.
- Do not strip the license headers or the notices banner from minified files.
- Publishing a host, as GitHub Pages does here, serves these files beside the code they cover,
  so published sites carry the notices without extra work.

## Build and authoring tools

These packages are installed by `npm install` for chart rendering, validation, and the Canvas
build. They are never copied into `shell/` or a published site, so they create no redistribution
obligations. Each package's license is in its `node_modules` directory.

| Package | Version | License | Used for |
| --- | --- | --- | --- |
| semiotic | 3.8.3 | Apache-2.0 | Offline chart rendering |
| sharp | 0.35.3 | Apache-2.0 | Raster export, pulled in by semiotic |
| `@img/sharp-*` platform binaries | Matches sharp | Apache-2.0 and LGPL-3.0-or-later (libvips) | Native image processing |
| jsdom | 29.1.1 | MIT | Server-side rendering for semiotic |
| gifenc | 1.0.3 | MIT | Pulled in by semiotic |
| parse5 | 8.0.0 | MIT | HTML parsing in validators |
| esbuild | 0.28.1 | MIT | Canvas build |

Charts rendered by the chart skill are the author's output, not part of these packages.
Never commit `node_modules` or package the native binaries with a host, because that would
redistribute the LGPL components.

The [iconography skill](https://github.com/prabinpebam/slate/blob/main/visualization/skills/iconography/SKILL.md)
holds the full sourcing and attribution rules. Lucide icons appear only inside the Canvas
application through `lucide-react`; authored content must not use them.

## Updating a component

1. Replace the vendored file, or update the dependency and run `npm run build:canvas`.
2. For a vendored file, update its license text in `shell/vendor/LICENSES/`, the table in
   `shell/vendor/README.md`, and `VENDORED_COMPONENTS` in `scripts/third-party-notices.mjs`.
3. Update the tables on this page.
4. Run `npm run test:third-party-notices`. It fails when a bundled or vendored component is
   unrecorded, a recorded version no longer matches the shipped file, a license text is missing,
   or this page omits a component.
